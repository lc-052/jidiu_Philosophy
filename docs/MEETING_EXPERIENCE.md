# 圆桌与游戏阅读优化（1.0.6）

## 讨论节奏

首轮请受邀者各自表达立场；追问轮保留全体成员和历史上下文，但最多指定三位发言。若回应某条发言，原作者优先入选，其他席位轮换，模型从名单中选择相关回应。提示要求围绕一个具体分歧回应、补充或反驳，不重复各自的小论文。客户端校验发言人数、参与者、唯一消息和回应对象；内容质量仍受所选模型影响。

第三轮起，正常讨论请求携带 `includeSummary=true`，在同一次模型调用内附带小结，不额外自动发出另一笔请求。需要提前整理时，第二轮后可点“整理分歧（调用一次模型）”。已有小结作为当时的快照保留，后续新轮次可形成新的小结。

## 分歧小结

中立卡片区分具体分歧和有依据的共同点，不判定胜者。共同点缺少依据时可以为空。每项包含真实发言 ID，可点回原发言并高亮。显示“截至第几条发言”，避免把早期整理误认作最新观点。

三场固定演示各有固定小结，明确标注只依据演示发言；用户追问不会使演示生成新的回复或小结。已有旧演示没有自动补写内容。

## 用户插话

点击哲学家的消息后，底部显示回应对象。可以直接回应，也可请求“解释这个概念”或“举个生活中的例子”。快捷操作只填入草稿，不自动发送或调用模型。定向消息以 `responseTo` 保存到 Room；草稿和回应目标通过 SavedStateHandle 恢复。发送后清除目标，新开会议不会沿用旧的回应对象。

## 会议顶部

滚动阅读时收起成员和较大的话题区，只留简短话题；成员按钮可展开或收起席位。新会议操作移入会议菜单，菜单也提供会后念头入口。长话题和昵称使用省略显示，完整话题仍在讨论顶部和历史中。

## 会后念头

可以记录当前更认同哪位、改变想法的地方和自己的结论，也可以暂不选择立场。信息只在本地保存，不参与思想画像评分，不要求给讨论一个最终答案。历史列表显示结论摘要，重新打开历史会议先显示自己的念头。可以继续讨论、重新编辑。

Room schema 从 1 升至 2，增加 MeetingThoughtEntity 和 MeetingInsightEntity；显式 Migration 保留旧会话、消息、收藏、回答与 Reflection。清除所有本地数据时，会话关联的小结和念头一起级联清除。

## 游戏阅读

八个主题先显示不剧透的生活问题与三种直觉选择，再展开“在作品里怎么看”“背后的哲学”“不要急着等同”和资料来源。可能剧透的内容仍需单独点开。末尾回看刚才的选择，允许回到问题重想。直觉选择只保留本次页面状态（含重建恢复），暂不纳入永久历史或思想画像。

## API 协议

旧字段保留。RoundTableRequest 新增可选字段：

- mode：discussion / summary，默认 discussion。
- speakerIds：本轮可发言的参与者，默认 philosopherIds；完整上下文成员仍用 philosopherIds。
- replyTo：被定向回应的消息 ID，可为空。
- includeSummary：正常讨论同时返回小结，默认 false。

RoundTableResponse 新增可选 summary：

```json
{
  "topic": "努力需要终点吗？",
  "messages": [],
  "summary": {
    "disagreement": [{"text": "如何衡量努力的价值？", "messageIds": ["真实消息ID"]}],
    "commonGround": []
  }
}
```

summary 模式的 messages 必须为空；普通发言轮仍返回 messages，includeSummary=true 时同时包含 summary。每条小结需要 1–6 个有效发言 ID；分歧 1–4 项，共同点 0–4 项。Backend 和手机直连接口使用同一原则。使用自定义 Backend 时须同步支持扩展字段，缺少有效小结会明确报错，不以假内容补齐。

## 验证边界

使用本地 HTTP 模拟模型验证实际网络请求、定向上下文、独立小结和第三轮自动小结，未调用付费模型。真实模型对哲学观点、相关性、措辞和共识的判断仍需要使用者审视，引用 ID 的校验只证明发言存在，不证明解读一定正确。
